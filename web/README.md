# Explorer page (source)

The app is one offline HTML file, `src/llm_lab/assets/explorer.html`, generated from this folder.
It has five pages, switched by the URL hash: **Architectures** (`#architectures`, or a tab such as
`#mla`), **Multimodal** (`#multimodal`, or `#multimodal/<modality>/<model>` such as `#multimodal/audio/voxtral`), **Retrieval**
(`#retrieval`), **Reasoning** (`#reasoning`) and a placeholder for **Agents**. A new page is a `<div class="page" data-page="…">` in `template.html`,
a link in `.pages` and its name in `PAGES` in `app.js`.

| File | What it holds |
|---|---|
| `src/content.js` | Model dimensions, all text and TeX, cache arithmetic, the decoding methods. Data and pure functions, no DOM. |
| `src/app.js` | Diagrams, pop-ups, step cards, tour, pages, keyboard handling. Shares its helpers as `window.LABUI`. |
| `src/mm-content.js` | Multimodal page: the four vision-language models, resize rules, token and cache arithmetic, M-RoPE positions, Gemma's mask, all text. Mirrors `llm_lab/reference/vision.py`; no DOM. |
| `src/mm-media.js` | Multimodal page, other modalities: audio, video, speech out, image out, all together. Models, rules, step texts; mirrors `llm_lab/reference/{audio,video,speech,imagegen}.py`; no DOM. |
| `src/mm-app.js` | Multimodal page: the modality switch, the pipeline diagrams, the example image and sound, “Your image / audio / video…”, step cards, up-close figures, cost comparisons. Draws on first visit. |
| `src/retrieval-content.js` | Retrieval page: the five documents, example questions, tokenizer, vocabulary, BM25 and TF-IDF weights, query vectors, q · d, and the dense ranking from `embeddings.json`. Mirrors `llm_lab/reference/retrieval.py`; no DOM. |
| `src/retrieval-app.js` | Retrieval page, sparse and dense mode: input → vocabulary or tokens → sparse or dense vectors → output, the three boxes on the arrows and their details, the RAG prompt. |
| `src/reasoning-content.js` | Reasoning page: DeepSeek-R1's architecture (parameters, KV cache, the expert router), the prompt template and a thinking trace. Mirrors `llm_lab/reference/reasoning.py`; no DOM. |
| `src/reasoning-app.js` | Reasoning page: the thinking diagram (context window, one forward pass, KV cache; step, play, jump) and the details of each part. |
| `src/learned-sparse.json` | opensearch-neural-sparse-encoding-v2-distill's tokens and nonzero term weights (`[id, token, weight]`) for the same texts. Same script; for now a placeholder too. |
| `src/embeddings.json` | all-MiniLM-L6-v2's tokens and vectors for the five documents and the example questions. Generated by `scripts/make_embeddings.py`; for now a placeholder (`--placeholder`: random unit vectors, a plain word split with provisional ids, `"placeholder": true`), noted in the page's footer and by the tests. |
| `src/template.html` | Markup and CSS (light and dark). |
| `src/examples.json` | The example inputs: sentence, candidate next tokens with illustrative logits, beam-search second steps. |
| `src/tokens.json` | `examples.json` plus each model's real tokenization of it. Generated by `scripts/make_tokens.py`. |
| `build.mjs` | Checks every TeX string with Temml, subsets the math font, inlines everything into one file. |

## Build

```bash
cd web
npm install                       # temml
pip install fonttools brotli      # font subsetting
python3 scripts/make_embeddings.py                    # only after changing the Retrieval texts (needs huggingface.co)
MATH_FONT=/path/to/latinmodern-math.otf npm run build
cd .. && python -m pytest tests/test_explorer.py tests/test_explorer_browser.py
```

`MATH_FONT` defaults to the TeX Live location
(`/usr/share/texmf/fonts/opentype/public/lm-math/latinmodern-math.otf`).

## Example inputs

After editing `src/examples.json`:

```bash
TOK_DIR=<folder with the @lenml/tokenizer-* npm packages> \
DEEPSEEK_LLM_GGUF=<llama.cpp models/ggml-vocab-deepseek-llm.gguf> \
python3 scripts/make_tokens.py
```

It uses `@lenml/tokenizer-{gpt2,gemma,qwen2_5,qwen3,deepseek_v3}` (ports of the Hugging Face
tokenizers) and, for DeepSeek-V2-Lite, byte-level BPE over llama.cpp's DeepSeek LLM vocabulary
(`scripts/bpe_gguf.py`). It refuses a candidate that is not a single token for every model, and a
sentence longer than the diagram's 10 rows.

## Rules the content follows

- Every dimension comes from the model's published `config.json`; the tests check the page against
  `llm_lab.reference.config`.
- No weights are loaded. Next-token logits, beam-search second steps and the speculative-decoding
  draft are illustrative and labeled, unless a bundle from `llm_lab.next_token` is embedded.
- Attention weights, index scores, expert choices and gate values in the diagrams are schematic.
- Cache sizes assume 16-bit values.

Licences: Temml (MIT) is inlined in the page; the font is a renamed subset of Latin Modern Math
(GUST Font License).

## Reasoning page

One diagram of thinking, with DeepSeek-R1 as the example (title, lead and four key facts above it, the
sources below). No benchmark results and no training: the page is about how the model thinks.

- **Controls**: the pass number and its phase (prefill, thinking, closing the thought, answering), step
  ◀ ▶, play, a slider over every pass, and jumps to the first pass, the “Wait”, `</think>` and the last pass.
- **Context window**: the prompt (the paper's template, paraphrased, ending in `<think>`) and everything
  written so far; this pass's input token is outlined, its output filled.
- **The loop**: the newest token goes down into **one forward pass** — input → *Embedding* → ×61 layers
  (*Attention*, with the number of positions it reads, → *Experts*, the router's 8 of 256 from
  DeepSeek-V3's rule on demo scores) → *LM head* → *Sample* (schematic bars) → output — and the output
  goes back up into the context. In the first pass the whole prompt goes in at once (prefill).
- **Stop?**: on the way back up, the check after every token: `</think>` ends the thinking, `<eos>`
  the reply, and the count against the 32,768-token generation limit. Its details list the four ways
  thinking stops (the model's two tokens, the length limit, a thinking budget) and what the paper, the
  README and s1's budget forcing say about when.
- **KV cache**: attention reads all of it and adds one entry per pass; a bar of prompt, thinking and
  answer entries, with its size in bytes.
- **Details**: every part opens a panel below (a formula, what it does, the numbers); the cache's panel
  has cache size, operations and cache reads for longer contexts, computed from the architecture.

`tests/test_reasoning.py` checks the page's configuration against `llm_lab.reference.config.DEEPSEEK_R1`,
its parameter counts and cache against `llm_lab/reference/reasoning.py` and against transformers'
`DeepseekV3ForCausalLM` (built on the meta device), and its router against the reference MoE layer.
`tests/test_reasoning_browser.py` steps through the diagram in a browser.

## Retrieval page

The figure follows one query from left to right: **Input** (the query, picked from a dropdown, and
five documents) → *unique words* → **Vocabulary** (`id | term`, ids in order of first appearance) →
*Weighting* (BM25 or TF-IDF) → **Sparse vectors** (one row per term, one column per vector: q is 0/1,
each dᵢ holds its document's weights) → *score query against each doc* → **Output** (scores sorted;
“select k” picks the documents that go into the prompt). Each box on an arrow is a button that opens
its details below the figure: the tokenizer on a chosen document, the weight formula with every
number of a chosen entry, and the sum `q · d` for every document. The vocabulary and the vectors
share their rows (terms 01–16, the query's terms, the last term, with ⋮ between) and line up across
the Weighting box. The rows left out are 0 in q, so they never change a score.

**Learned sparse mode** keeps the same input and output: *Tokenize* → **Tokens** → *Encoder + MLM
head* (opensearch-neural-sparse-encoding-v2-distill: every position scores all 30,522 vocabulary
tokens; a token's weight is the max over positions of log(1 + ReLU)) → **Learned sparse vectors**:
one row per vocabulary token the query weights (its 16 largest, in vocabulary order), columns q and d₁…d₅, expansion terms (weighted but not in the text) in purple → the
*score*, over the tokens where both are nonzero. Its details show the largest weights of a document
and of the query, and the three rankings side by side.

**Hybrid mode** runs BM25 (or TF-IDF) and dense retrieval on the same question: *Two retrievers* →
**Two rankings** (the sparse list holds only documents that share a term with the question) → *Fusion*,
with a switch between reciprocal rank fusion (Σ 1/(60 + rank), Cormack, Clarke & Büttcher 2009) and a
weighted sum (α = 0.5) of min-max normalized scores → **Fused scores** (each list's share and the sum)
→ *sort* → **Output**. `tests/test_retrieval.py` checks both fusions against `hybrid_scores` in
`llm_lab/reference/retrieval.py`.

**Dense mode** (the tabs at the top: Sparse, Learned sparse, Dense; each sets the title, a lead and a row of key facts, as on the Architectures page) keeps the input and the output and swaps the middle:
*Tokenize* (WordPiece, the model's fixed vocabulary of 30,522) → **Tokens** of the query or a
document → *Encoder* (all-MiniLM-L6-v2: 6 layers, mean of the token vectors, scaled to length 1) →
**Dense vectors** (one row per dimension, 1–16, ⋮, 384; every entry nonzero) → the same *score* box,
whose details put the sparse and the dense ranking side by side. The page runs no model: the vectors
of the five documents and the example questions come from `src/embeddings.json`, which is why the
query is picked from a list. While that file is a placeholder, its dense ranking is illustrative only
(the footer says so). Three examples are worded unlike their document (“something to eat”,
“a train”) or have no answer (“parking”), where the two rankings part ways.

BM25 uses k₁ = 1.2, b = 0.75 and Lucene's idf, so `q · d` is the usual BM25 score. TF-IDF uses
scikit-learn's smoothed idf and L2-normalized rows; cosine similarity would also scale `q`, which
divides all scores by the same number and leaves the order unchanged. `tests/test_retrieval.py`
runs the page's code in node and compares every weight and score with `llm_lab/reference/retrieval.py`,
whose TF-IDF weights are compared with scikit-learn's `TfidfVectorizer`.
