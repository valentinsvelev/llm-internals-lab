    KV cache per token, per layer

    Values stored per token for 16 query heads of dimension 128, the head layout of DeepSeek-V2-Lite. GQA uses 4 groups; MLA a 512-dim latent plus a 64-dim rotary key; DSA adds a 128-dim index key.

    During generation the KV cache, more than the arithmetic, limits how long a context or how large a batch fits in GPU memory, and reading it back slows every new token. That is why these variants exist.

    MQA shrinks the cache the most but can cost quality. GQA recovers most of that quality at close to MQA's speed (Ainslie et al., 2023). DeepSeek reports MLA outperforming MHA in its ablations while caching about as much as GQA with 2.25 groups.

    The two newer designs attack the growth with length itself. Gated DeltaNet replaces the cache with a fixed-size memory, so Qwen3-Next keeps a per-token cache in only 12 of its 48 layers. Sparse attention still stores every token, but each new token reads only the 2,048 that its indexer selects, so the work per token stops growing with the context.

    * Gated DeltaNet stores nothing per token. Each layer keeps one fixed-size state instead: 16 heads × 128 × 128 = 262,144 values at the sizes compared here, however long the context.

            What the model receives 
            
      
            
    
            
    
            Five fictional documents about a made-up aquarium. Sparse: terms are lowercase letters and digits, 35 stop words removed, simplified plurals; BM25 with k₁ = 1.2 and b = 0.75 and the smoothed idf of Lucene; TF-IDF with the smoothed idf of scikit-learn and each document vector scaled to length 1; the query vector has a 1 for each of its terms. Dense: the vectors come from web/src/embeddings.json, written in advance for the five documents and the example questions by web/scripts/make_embeddings.py with all-MiniLM-L6-v2 (mean of the token vectors, scaled to length 1). Learned sparse: the weights come from web/src/learned-sparse.json, written by the same script with opensearch-neural-sparse-encoding-v2-distill (max over positions of log(1 + ReLU) of the masked-language-model logits). Both are why the query is chosen from a list. Hybrid: the BM25 (or TF-IDF) and the dense ranking, fused by reciprocal rank (k = 60) or by a weighted sum (α = 0.5) of min-max normalized scores.  No model or API is called by this page, and the example answers are written in advance.
            The same rules are runnable Python in llm_lab/reference/retrieval.py; its TF-IDF weights are tested against scikit-learn’s TfidfVectorizer.
