    KV cache per token, per layer

    Values stored per token for 16 query heads of dimension 128, the head layout of DeepSeek-V2-Lite. GQA uses 4 groups; MLA a 512-dim latent plus a 64-dim rotary key; DSA adds a 128-dim index key.

    During generation the KV cache, more than the arithmetic, limits how long a context or how large a batch fits in GPU memory, and reading it back slows every new token. That is why these variants exist.

    MQA shrinks the cache the most but can cost quality. GQA recovers most of that quality at close to MQA's speed (Ainslie et al., 2023). DeepSeek reports MLA outperforming MHA in its ablations while caching about as much as GQA with 2.25 groups.

    The two newer designs attack the growth with length itself. Gated DeltaNet replaces the cache with a fixed-size memory, so Qwen3-Next keeps a per-token cache in only 12 of its 48 layers. Sparse attention still stores every token, but each new token reads only the 2,048 that its indexer selects, so the work per token stops growing with the context.

    * Gated DeltaNet stores nothing per token. Each layer keeps one fixed-size state instead: 16 heads × 128 × 128 = 262,144 values at the sizes compared here, however long the context.

          Up close

          What one image costs

          Image tokens are paid for twice: they take up context, and every one of them stores keys and values in every layer, like a word. A 576-token image is about 14% of LLaVA-1.5’s 4,096-token context.

          The four designs trade detail for cost differently. LLaVA and Gemma spend the same on every image, so a small image is overpaid and a large one loses detail (LLaVA crops it, Gemma squashes it). Qwen3-VL pays in proportion to the pixels, so detail is kept but a large image is expensive. Llama 3.2 keeps the text short — one token per image — but caches 6,404 image positions in each cross-attention layer, empty tiles included.

          Dimensions come from the official config and preprocessor files of . Image sizes, tiles, patch grids and token counts follow the transformers image processors, and parameter counts are those of the transformers models. No weights are loaded and nothing is computed from your image except its size and, for the mosaics, its colours; it never leaves this tab. Cache sizes assume 16-bit values.

          The resize rules, the connectors, Qwen’s 3D positions, Gemma’s image mask and Llama’s gated cross-attention are also runnable PyTorch in llm_lab/reference/vision.py, tested against Hugging Face transformers.
